# opencode headless benchmarks (2026-10-11)

opencode 1.18.23, model `opencode/big-pickle` (free), on the user's laptop: 8 threads, 15 GB RAM, under memory pressure at the time (~2.5 GB available, 15 GB swap used). Single runs, so treat as rough sizes. Memory is USS/RSS summed over the process tree, sampled every 0.2 s. Scripts in [scripts/](scripts/).

| Scenario | Memory | CPU | Time |
|---|---|---|---|
| CLI cold start (`--version`) | – | – | 0.43 s |
| `opencode serve` until `/doc` answers | – | – | ~2.7 s |
| `opencode serve` idle, 30 s | ~290 MB steady, 350 MB peak | ~1% | – |
| `opencode run`, one-word reply | ~700 MB peak | 5–7 CPU-s | 7–10 s |
| `opencode run`, write + compile + run a C file | ~705 MB peak | 7.3 CPU-s | 20 s |
| 3 concurrent runs, separate processes | 1.41 GB total | – | 15 s |
| 3 concurrent runs, one shared `serve` (`--attach`) | 1.16 GB total | – | 23 s |
| User's live TUI session, 4.7 h old | 825 MB RSS + 279 MB swapped | ~100% of a core sustained (124% lifetime avg) | – |

Notes:
- Budget ~0.5–1 GB per agent for the harness; long sessions grow (~1.1 GB at 4.7 h).
- Headless idle CPU is ~1%; the TUI session used about a full core continuously (can't separate TUI cost from agent work).
- A shared server saved ~20% memory but was slower; separate processes are fine and isolate crashes.
- `--pure` disables plugins but **not** MCP servers: every run starts the global config's MCPs (a `github-mcp-server` Docker container and the Ghidra bridge in the user's config). Benchmarks marked "noMCP" used `XDG_CONFIG_HOME` pointing at an empty config.
- Benchmark sessions are titled `pixel-bench` in the user's opencode history.

Reproduce:
```
python3 scripts/bench.py <label> <idle_secs or 0> -- opencode run --pure -m opencode/big-pickle "Reply with exactly: OK"
LIVE=<pid to exclude> bash scripts/conc.sh standalone|attach 3
```
(`conc.sh` expects a `cfg/opencode/opencode.json` next to it for the MCP-free config.)
